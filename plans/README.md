## Recommended execution order

```
001 → 005 → 009 → 004 → 002 → 003 → 006 → 007 → 008
```

Reasoning:

1. **001 first.** It removes `command-bar.tsx`'s animation entirely, which
   several other plans (002, 006) reference as "check whether this file
   still applies" — running it first avoids ambiguity for those.
2. **005, then 009** — both touch `experience-timeline.tsx`; 005 removes a
   whole block (the inner height animation), 009 tweaks one number on a
   line 005 doesn't touch. Doing 005 first just keeps the diff sequence
   tidy; there's no functional conflict either order.
3. **004 before 002** — this is a **hard dependency**. Both plans edit the
   same `initial`/`animate` props in `profile-card.tsx`,
   `achievements-card.tsx`, `experience-timeline.tsx`, `discord-presence.tsx`,
   `coding-stats-panel.tsx`, `dock.tsx`, and `Sandbox.tsx`. 004 converts
   `x`/`y`/`scale` shorthand to `transform` strings; 002 then adds
   `shouldReduceMotion` conditionals on top. Running 002 before 004 means
   004's "current code" excerpts won't match what it finds (both plans'
   Boundaries sections instruct the executor to STOP and report on that
   drift rather than improvise) — so respect this order.
4. **003** is independent (different file, `theme-toggle/index.tsx`) — can
   technically run anytime, grouped here with the other accessibility work.
5. **006, 007, 008** are independent, low-risk, cosmetic/consolidation
   passes — safe to run last, in any order among themselves.

## Notes

- Every plan is written to be independently self-contained (exact file
  paths, current code, target code) per the skill's hard rules — the
  ordering above is a recommendation to minimize merge/drift friction, not
  a strict requirement. If you run them out of order, each plan's
  Boundaries section tells the executor to stop and report rather than
  guess when the code it finds doesn't match its "current" excerpt.
- None of these plans touch `components/ui/*` (shadcn-generated
  primitives) except reading `components/ui/button.tsx` for context in
  plan 007 — that file itself is not modified by any plan.
